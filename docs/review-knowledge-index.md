# 评阅知识点索引

知识点索引保存在本地 `review-knowledge-index.json`，与 PDF 库、题库和提交历史分开。它是已保存评阅与教材片段之间的轻量关联，不会概括整本书，不会发起额外模型请求，不会自动上传 PDF。

## 使用与状态

- 生成索引时，只读取指定的、已经成功保存的提交。每个评分项生成一个知识点，标题和摘要来自该项现有评阅；没有评分项时使用整体反馈。摘要最多 600 字符，并明确标记截断。
- 新节点为 `pending`（待关联）。系统不会把评阅中的书名、页码或模型声称的引用当作证据，也不会为了填满索引制造教材对应关系。
- 在本地 PDF 检索中选择实际片段后，可显式建立关联。每个节点最多关联 3 个片段；必须与提交快照的学科一致。
- `linked`（已关联）意味着本次读取验证了原提交、原 PDF 的 SHA-256 和当前片段内容。
- `stale`（待核对）意味着原评阅、PDF、学科或片段内容已经改变、缺失或无法验证。这样的节点仍保留旧关联的身份，但不会返回片段正文，也不会自动改绑相同页码上的新内容。重新选择实际片段后才能更新关联。
- 旧提交如果没有题目快照，学科保持未知，不能凭当前题库或文件名猜测关联。旧历史本身不修改。
- 知识点标签可以编辑。解除关联、移除节点只改变本地索引，不删除 PDF、不改动提交或原评阅。移除节点会留下有界的删除标识，重复生成不会使它复活。

索引最多保留 1,000 个节点和 10,000 个删除标识。超限操作明确失败，不会自动裁掉旧历史。损坏的索引文件不会自动清空或覆盖，应先保留备份。

## 可信边界与集成

`ReviewKnowledgeIndex` 的构造器由主进程提供三个回调：

- `resolveAttempt(id)`：从持久化 `StudyService` 状态读取真实 `Attempt`，而不是接收渲染进程提交的评阅文本。
- `resolveChunks(ids)`：调用 `LocalKnowledgeLibrary.resolveChunks`，只通过片段 ID 获取当前规范标题、学科、物理页码和正文。
- `verifyDocument(id)`：调用 `LocalKnowledgeLibrary.getBytes(id)` 并丢弃返回值；该方法验证真实 PDF 字节与内容地址 SHA-256 一致。

索引保存提交 ID、题目 ID、评阅身份摘要、反馈来源、短摘要、用户标签和引用元数据。引用包括 PDF SHA-256、物理页码、片段 ID 和片段正文 SHA-256，不复制 PDF 全文、题目、作答、模型配置或凭据。物理页码从 1 开始，不推测教材印刷页码。

`refresh({attemptIds})` 每批最多接受 50 个提交 ID，重复调用保持标签和关联不变。节点身份由规范提交快照与评阅来源计算；原评阅发生变化时保留旧节点并标记失效，新的评阅生成新身份。异步关联结束前再次检查原评阅，修改操作使用 `expectedRevision` 防止旧界面覆盖新编辑。请求可传入主进程 `AbortSignal`，保存前检查取消；提交到磁盘之后的取消不会隐藏已保存结果。主进程只可向界面展示 `ReviewKnowledgeError` 的固定公开消息目录；不能转发其他异常的原始消息、文件路径或回调内容。

`list`、`get` 和本地 `resolveEvidence` 每次调用都重新验证来源。一次操作内，同一 PDF 的字节验证和同一片段的解析会合并；不会跨操作跳过校验。书名更新时显示当前规范书名，内容哈希保持不变。

`resolveEvidence(nodeId)` 只返回当前仍有效的本地规范证据。它本身不是远程工具权限：调用模型/远程工具时，仍必须检查用户本次选中的同学科 PDF、页码或章节范围，以及现有同意和 3 个片段、总计 1,200 字符的工具共享预算。保存过的关联不扩大检索范围，也不提供新的上传授权。

## 验证

`tests/review-knowledge-index.test.ts` 使用合成提交、规范解析回调和原创合成 PDF 覆盖：身份绑定、重启与幂等、标签与关联 CAS、删除标识、旧历史未知学科、跨学科拒绝、真实 PDF 哈希、提取文本变化、标题变更、缺失/损坏来源、索引损坏保护、容量保护、取消、异步源变化，以及失效证据不返回正文。测试不使用真实凭据或网络模型。
