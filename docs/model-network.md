# 模型连接与 Clash Verge

在「模型设置」为当前配置选择网络连接方式，再保存：

- **直连**：沿用旧版行为，不自动采用系统代理。Clash Fake-IP 仍会被公网地址检查拦截。
- **系统代理**：读取系统为本次目标选择的路线。支持本机回环 HTTP 代理；系统明确返回直连时，继续使用带 DNS 安全检查的直连。
- **本机代理**：填写 Clash 显示的 HTTP 或混合代理端口，例如 `http://127.0.0.1:7890`。端口只是示例，请使用自己已配置的端口。支持 `[::1]`，不接受远程地址、SOCKS、认证信息或额外路径。

获取模型、测试 API、实际模型生成和 Agent 工具请求共用这项选择。获取模型和测试 API 会使用编辑器当前值；实际生成使用已保存值。切换网络时会取消旧请求。旧配置默认直连，不会未经选择改变请求路线。

本机代理模式通过 HTTP CONNECT 建立到原始域名的 HTTPS 隧道，API Key 和正文只在通过证书校验的 TLS 连接中发送。只对经选定本机代理的域名解析允许 `198.18.0.0/15` Fake-IP；其他私网地址仍被拒绝。代理需要被用户信任，其上游解析和路由由代理负责。应用不会修改 Clash、操作系统代理、证书或防火墙设置，也不会关闭 TLS 验证。

代理不可用、要求认证或返回错误时会明确失败，不自动改走直连。服务返回重定向时不会转发密钥，请改填最终 API 基础地址。系统模式若无法获得受支持的路线，可明确选择本机代理并填写已有 HTTP/混合端口。

本地回归使用合成凭据、DNS 测试替身及仅用于测试的证书与回环代理。它验证传输与安全边界，不代表用户的真实 API、Clash 实例、套餐额度或模型生成质量已验证。

实现依据：[Electron 代理模式](https://www.electronjs.org/docs/latest/api/structures/proxy-config)、[Node HTTPS](https://nodejs.org/api/https.html)、[Node TLS](https://nodejs.org/api/tls.html)。
