# 学科提交时间线

「练习记录」按语文、数学、英语、思想政治、历史、地理分别排列已保存的提交。可筛选单一学科或浏览全部学科；每科最新在前。同一道题重复提交仍是独立节点，不合并答案相同的记录。节点显示提交时间、该学科中的留存序号、得分、答案摘要和反馈，点击后打开该次提交的完整审阅。

## 数据与只读边界

- 唯一来源是已有的 `StudyState.attempts`。组件不创建新存储、不修改学习数据，也不会把草稿、正在请求的评阅、失败/取消的评阅或模块编辑检查点转换为提交。
- 答案、选择、数学/地理绘图、模块结构、评分项、得分、反馈和解析来自这次 `Attempt`。题面和学科来自同一次记录的 `questionSnapshot`，不从当前题库补写为历史事实。
- 显示模型建立脱离原对象的深冻结副本。重新导入或编辑题库、编辑当前草稿不会替换原提交的内容。
- 点击仅调用 `onSelectAttempt(attempt.id)`。不恢复答案、不覆盖草稿、不触发评分、也不调整模块编辑版本。
- 这些节点是按学科分组的时间线。没有保存的父子关系，因此不推断分支、重做起点或版本血缘。模块编辑器中的撤销/重做与「版本时间树」仍是单独的编辑功能。
- 只有成功评阅并成功保存的提交才进入 `Attempt[]`。分数为 0 的已保存提交仍是真实记录，照常显示。

## 旧记录与不完整元数据

旧版记录可能没有题面快照。这类记录保留原答案、得分和反馈，并显示「题面快照缺失」；无法确认提交时学科时放入「学科未知」。即使当前题库有同 ID 的题目，也不会借其当前学科重新归类。如果提供当前题库标题作定位参考，必须显示「当前题库标题（非提交快照）」。快照 ID 与提交的题目 ID 不一致时也按缺失快照处理。

时间按应用运行电脑的本地时区显示，含年月日和秒。无效时间显示「提交时间不可用」，记录仍保留，排在该学科可解析时间之后；相同时间按原数组追加顺序倒序排列。序号是同学科留存记录的顺序，不是题目重试次数，也不保证能重建缺失时间的真实先后关系。

## 集成

`SubmissionTimeline` 接收 `attempts`、可选的 `questions`、可选的 `selectedId` 和 `onSelectAttempt`。它包含标题、学科筛选、计数、空状态与节点列表，适合放在历史页面的列表卡片中。外部选择了被当前筛选隐藏的提交时，筛选会切到对应学科。组件只负责选择；完整审阅面板也应保持同样的快照与旧记录标注边界。

样式使用 `--app-accent`、`--app-text`、`--app-text-muted`、`--app-border`、`--app-surface`、`--app-background` 和 `--app-warning-text`，缺省为奶油底色与紫色强调。筛选可换行、列表可滚动；按钮提供原生键盘操作、选中状态和焦点轮廓。

## 验证

`tests/submission-timeline.test.ts` 覆盖六科学科隔离、多次提交、零分提交、快照深冻结、当前题库不可冒充历史、缺失/错误元数据、乱序/无效时间、筛选、只读点击、空状态、安全文本转义，以及真实 `StudyService` 的草稿 → 待处理/失败 → 成功保存/重启读取路径。

组件静态渲染与按钮回调测试不能替代浏览器中的视觉、键盘切换和窄屏布局验证。浏览器验证结果应由应用集成后的检查单独记录。
