# 私有知识包：一次导入多科原始 PDF

知识包是一个普通文件夹，里面放 `pack.json` 清单和清单列出的 PDF（或原始 PDF 的二进制分片）。在桌面应用的知识库中选择“导入教材资料包”，再通过系统文件选择器选中 `pack.json`。不需要终端、不需要手动拼接文件，也不会自动扫描其他目录。

这是一种本地导入格式，不是在线教材下载器。只有你拥有合法使用权限的资料才应放入自己的私有包。真实教材、扫描件、水印页、答案库及私有知识包不应提交到公开仓库或随公开应用发行；仓库测试只使用自编合成 PDF。

## 单个 PDF 的清单格式

```json
{
  "version": 1,
  "title": "我的六科资料",
  "documents": [
    {
      "file": "chinese.pdf",
      "sha256": "这里必须替换为原始文件的64位小写SHA256十六进制值",
      "subject": "chinese",
      "title": "语文资料",
      "edition": "根据封面推定的版本，待核对",
      "editionConfirmed": false
    }
  ]
}
```

上面的哈希是说明性占位符，不能直接导入。制包方应提供与交付文件对应的实际哈希。

- `version` 必须是 `1`；`title` 是知识包名称。
- `documents` 必须包含 1–12 份文档，不要求凑齐六科，也允许同科多本。
- `file` 是同一目录中的普通 PDF 文件名，不是绝对路径、相对路径、URL 或设备名。
- `sha256` 是整份 PDF 原始字节的 64 位小写十六进制 SHA-256。
- `subject` 只接受 `chinese`、`math`、`english`、`politics`、`history`、`geography`，分别是语文、数学、英语、思想政治、历史和地理。
- `title` 是文档显示标题。
- `edition` 可省略，默认空字符串，表示版本未知。填写出版社、教材系列或修订信息也不代表版本已经核实。
- `editionConfirmed` 可省略，默认 `false`；只有已经核对原件版本时才设为 `true`。已确认时 `edition` 不能为空。
- 未知字段会被拒绝。清单不接受远程地址、题库、参考答案、任意脚本、命令或自动章节推断。

## 交付较大 PDF：自动合并原始字节分片

如果文件交付渠道限制单个附件大小，制包方可以把原 PDF **按字节切片**，而不是按页面重新生成几份 PDF。`file` 和 `sha256` 仍代表完整原文件，增加按顺序排列的 `parts`：

```json
{
  "file": "english.pdf",
  "sha256": "整份原始PDF的64位小写SHA256值",
  "subject": "english",
  "title": "英语资料",
  "edition": "版本待核对",
  "editionConfirmed": false,
  "parts": [
    {
      "file": "english.pdf.part01",
      "sha256": "第1片的64位小写SHA256值",
      "byteLength": 18874368
    },
    {
      "file": "english.pdf.part02",
      "sha256": "第2片的64位小写SHA256值",
      "byteLength": 1000000
    }
  ]
}
```

这是单个 `documents` 项的说明性示例，哈希及长度必须替换为实际值。

- 每份 PDF 可使用 2–4 片；每片最多 18 MiB，合计最多 50 MiB。
- 分片名必须精确对应完整文件名加 `.part01`、`.part02`、`.part03`、`.part04`，从 01 开始按顺序列出，不能跳号、倒序或重复。
- 每片都必须有自己的 SHA-256 和准确 `byteLength`，合并后还必须通过整份 PDF 的 SHA-256 校验。
- 用户把 `pack.json` 和所有分片放在同一个普通文件夹，然后在应用中选择一次 `pack.json` 即可。使用 `parts` 时不需要另放合并后的 `english.pdf`。
- 合并在应用的私有临时目录中完成。导入后仍是一份文档，原有物理页码、水印、书签及所有原始 PDF 字节不因分片而变化。

## 边界与本地隐私

清单最多 32 KiB，整包最多 300 MiB，单份 PDF 最多 50 MiB、1500 个物理页。PDF 文本提取继续遵守知识库的文本量、解析时间和工作进程内存限制，不会静默截断大书。图片型扫描页保留原图及物理页，不会编造 OCR 文本。

文件名必须唯一；大小写或 Unicode 规范化后冲突的名字也会拒绝。清单也不允许重复整份 PDF 的哈希。路径分隔符、Windows 驱动符/设备名、符号链接、硬链接、目录和非普通文件都不会作为资料导入。ZIP 等归档文件不被解压或执行；额外的未列出文件不会被扫描。

只有主进程的系统文件选择器可以选择路径，网页界面不能通过 IPC 传入任意文件路径。流程没有网络请求、云上传、远程嵌入或自动向模型发送全文。选择并发送知识证据给模型仍受独立的知识库引用流程控制。

应用先检查全部文件的存在性、长度和边界，再把文件逐块复制到私有临时目录并验证全部哈希。只有这些检查全部通过后才逐本解析导入。因此，缺片、文件损坏或错包不会先导入几本再发现后面的校验失败。原文件不会被修改、去水印、覆盖或删除。临时副本在正常返回、失败或取消后清理；如果操作系统阻止清理，结果会附带警告而不会隐瞒已保存的文档。

## 取消、部分失败与重试

导入是**逐文档原子提交**，不是整包事务。全部哈希检查通过后，仍可能有某本 PDF 无法解析、被加密、超过页数限制或解析超时。该文档会显示失败原因，其他有效文档继续导入。

取消会停止正在进行的工作和尚未导入的文件。已经成功保存的文档仍然存在，结果会分别列出“已导入”“已存在”“失败”“待导入”。点击取消之前刚完成提交的文档仍会被如实计入成功数量。

修复缺片或损坏的包后，可以再次选择同一个 `pack.json`。已有文件按完整 PDF 的 SHA-256 去重，不重复保存，不覆盖标题、科目、版本、章节或原文。需要更改已存在文档的分类或版本时，请使用文档元信息编辑功能；重新导入知识包不会暗中改科。
